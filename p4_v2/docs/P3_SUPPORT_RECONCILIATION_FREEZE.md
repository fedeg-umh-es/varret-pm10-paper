# P3 Support Reconciliation Freeze

`PROJECT = P3`  
`CONDITION = lags_only`  
`TECHNICAL_NAMESPACE = p4_v2`

## Purpose and terminology

This document freezes a conservative primary support for the already executed
lags-only row-level predictions. It reconciles two historical support constructions
without retroactively rewriting protocol history.

- **A** is the historically estimated theoretical support universe.
- **B** is the support generated by the textual execution rule actually used.
- Neither A nor B is retrospectively labelled the correct universe, true universe,
  or original universe.
- The primary support is the **conservative intersection support** A ∩ B.

The support key is exactly:

`(station_id, condition, fold, origin, target_time, horizon)`

`model` is not part of the support key. Each retained support key is expected to
have one `xgboost_direct` row and one `sarima` row; persistence remains inline in
both prediction rows.

## Historical discrepancy mechanisms

The arithmetic is closed:

`3,632 + 177,843 + 3,561 = 185,036 = |B \ A|`.

The two mechanisms are kept distinct:

1. **Continuation after empty blocks:** 181,475 keys, consisting of 3,632
   `first_post_empty_block` keys and 177,843 `later_post_empty_block` keys. B
   continued according to the textual rule after a block with no eligible origins;
   A's historical estimator stopped at the first such block.
2. **Historical NaN / block-numbering divergence:** 3,561 keys. Historical
   NaN-handling and calendar-block numbering differ from the executed support
   labeling. These are not merged conceptually with continuation after empty
   blocks. The corresponding documented-only keys are retained in A \ B and are
   not regenerated.

The support-only reconciliation uses calendar, station, lag/target availability,
block, and key identity. No forecast error, skill, dynamic-fidelity diagnostic, or
event result was inspected to choose the primary support.

## Primary pairing gate

`PRIMARY_SUPPORT_PAIRING_GATE = PASS` is a data-integrity verification, not the
future `CASE_B_EXISTENCE_GATE`. For every conservative intersection support key,
the original prediction file contains exactly one XGBoost row and exactly one SARIMA
row. Shared support metadata (`y_true`, `y_persistence`, event threshold, protocol
hash, and source-panel hash) is identical across the pair. No prediction values were
repaired or altered.

## Downstream analysis rule

Primary scientific metrics, when separately authorized, must be computed first on
A ∩ B = 1,706,377 **conservative intersection support** keys only. B \ A is
reserved as an explicitly labelled sensitivity support. A \ B is excluded from
primary and sensitivity analyses because no executed prediction rows exist for it.

This phase does not construct the future train-only mean baseline or define any
CASE A/B/C/D classification. No forecasting models were retrained, no predictions
were regenerated, and no scientific metric was calculated in this freeze.
